## 2. 現在の戦略

Doberは、Threadsで認知と信頼を取り、公式LINEへリストインさせ、LINE内で教育・信頼形成・具体提案を行い、商材購入につなげる設計で運用する。

短期売上より、後から note、有料記事、アフィリエイト記事、商材を追加するたびに販売できるリスト資産を増やすことを優先する。通常投稿をすべて売り込みにしない。販売導線用の投稿は、note・有料記事・アフィリエイト記事・商材が追加されたタイミングで別途作る。

主導線:

1. Threadsで危機感・現在地チェック・自己改善の必要性を喚起する。
2. プロフィールや自然なCTAから公式LINEへ誘導する。
3. LINEでナーチャリングし、商材購入へつなげる。

短期マネタイズが必要な場合だけ使う導線:

1. Threadsからnoteへ遷移させ、有料noteを購入させる。
2. Threadsからnoteへ遷移させ、アフィリエイト商材を購入させる。
3. Threads本投稿で興味を作り、返信スレッドにアフィリエイトリンクをぶら下げる。

## 3. 投稿生成ルール

文体:

- 命令形で終わる文を使わない。断定形で言い切る。
- `——` は使わない。
- 本文冒頭は基本的に `▫️` を付ける。ただし短文断定型では付けない場合もある。
- 箇条書きは名詞止め、または動詞の辞書形でよい。

優先する投稿:

- 読者に危機感を与える投稿
- 現在地を測らせるチェックリスト
- 身体、睡眠、AV、酒、スクロール、金、女性、親、失恋、仕事、休日など生活実感のある具体物を含む投稿
- 「社会が思う成功 / 本当の成功」のような対比構造
- 「やめること / やること」のような行動整理
- 「平均 / 平均以上 / 最上位」のような階層分類

避ける投稿:

- アルファ/シグマ型。過去の高リーチデータでは優先度が低く、通常ローテーションから外す。
- 「お金の使い方」単体の訓話。お金テーマは、自由・仕組み・金で買えるもの/買えないものの構造に変換する。
- 有名人逸話単体。使う場合は規律・反復・退屈な習慣に接続する。
- 抽象的な短文断定だけの量産。

## 4. 現行フォーマット

投稿はAからGの7フォーマットで考える。通常はAからEを厚めにし、F/Gを補助的に入れる。週21本ならAからEを各3から4本、F/Gを各2から3本程度にする。Cは直近で突出実績があるため毎週2本以上入れる。

| 区分 | フォーマット | 内容 |
| --- | --- | --- |
| A | 危機・負債型 | 「人生が詰む」「人生を台無しにする」など、放置すると損失が返ってくる構造 |
| B | 基本基準・できないこと型 | 「ほとんどの男性ができないこと」「男の基本」など、現在地チェック |
| C | 社会が思う/本当の価値 対比型 | 見せる価値と実際の自由を対比する |
| D | 人工刺激・やめる/やる型 | AV、酒、スクロール、ジャンクフード、通知、見栄消費などを扱う |
| E | 退屈な規律型 | 早寝、筋トレ、自炊、読書、散歩、蓄財を新しいかっこよさとして提示する |
| F | 階層・ステージ分類型 | ステータス階層、上位1%、平均/平均以上/最上位などで読者を位置付ける |
| G | 恋愛・女性視点の選別型 | 女性が男を見る基準、結婚前確認、モテと生活管理を接続する |

## 6. 投稿スケジュール

- 07:30 JST

- 20:00 JST

DB登録時のUTC変換:

- 07:30 JST = 前日 22:30 UTC
- 12:00 JST = 同日 03:00 UTC
- 20:00 JST = 同日 11:00 UTC

## 7. 運用・分析基盤の現状

Dober運用は以下の3つに分かれている。

- `dober-content-strategy`: Dober向け投稿を作成し、draftとしてDBに登録する。
- `account-post-analysis`: 投稿メトリクスとフォロワー推移を集計し、分析レポートを生成する。
- `dober-strategy-review`: 最新分析レポートと過去高リーチ実例をもとに、`account_content_strategy` の参照実例セット更新を提案・適用する。

参照実例はDBの `account_content_strategy` でversion管理される。ローカルには `version4-high-impression-examples.json` があり、17件の高インプレッション実例が含まれている。

フォロワー数トラッキング:

- 2026-07-27の設計では、Threads APIの `followers_count` を日次で取得し、`account_metrics` に蓄積する方針。
- 実装ファイルとして `src/lib/threads-followers.ts` と `src/lib/collect-followers.ts` は存在する。
- 過去日付のフォロワー数はThreads APIからバックフィルできない。実装以降の推移だけを蓄積する。

publishログ:

- 2026-07-08から2026-07-19のDober週次分析で、publish失敗が19件発生していた。
- エラーは `Threads publish error: The requested resource does not exist` に集約され、03:00/11:00 UTCの失敗が多かった。
- 原因確定のため、`publish_logs` に成功・失敗の試行ログを残す設計がある。
- 実装ファイルとして `src/lib/publish-log.ts` と migration `supabase/migrations/20260720000000_publish_logs.sql` は存在する。
